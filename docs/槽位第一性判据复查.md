# 槽位第一性判据复查

> **代码基线**：`2742bee`。只复查、只落文档，**不改产品代码、不塌缩槽位体系**。
>
> 起因：读大一修 `523cda2` 的 §11 复杂度归因，说「每支持一种说法就复制一套分支」，
> 于是把 16 个原语塌缩成「一串编号 + 六条信任层」。这个诊断对那个 1.8 万行外围的
> 仓库成立。小一修要不要跟着动？本文逐个槽位核一遍再回答。
>
> **结论先说**：借判尺，不借手术。小一修的槽位锁死是「小而确定」这个产品定位的
> 护城河，不是病；但确实有 7 个槽位数学上是同一条线性行，属于受控的**说法枚举**，
> 以后不该再往这一类里加东西。

## 0. 先纠正清单里的一个数

此前待办清单写「15 个 closure 槽位」，不准。实地数过：

- `yxcore/closure.py` 的 `COMPILERS` 注册了 **14 个**走注入口的槽位。
- 「20 个主槽位 + 15 个参数槽位 = 35」是 `slots.py` 的**注册表总数**，
  其中还有 `strategy`（目标）、`deadline_delta`/`part_hours`/`part_arrival`（数据层）、
  `weather`/`hourly`（时间线）这些不走闭包的，别和闭包槽位混着数。

14 个是：`count_min, count_max, bucket_min, bucket_max, earliest, line_fixed,
cap_max, budget_max, before_seq, same_bucket, all_diff, sev_before, sev_gap, scope_only`。

## 1. 判尺：一个问题，两条纪律

大一修那把尺子可以原样借来用：

> **每想新增一个槽位，先回答：要么它能保证结果可信，要么它确实缩小了自由度、
> 并且拿得出数学上的必要。两条都答不上来，就不批。**

另外两条纪律写在 `closure.py` 开头，比槽位数量更值钱，复查时一并确认仍然有效：

1. **不引入大 M**。带指示变量的条件约束（「若 018 排入则 019 必须…」）一律不做。
   时序类要求涉及的任务必须被修，由 `apply` 把它们加进必修名单，于是每任务恰选一个
   候选，和式直接就是它的时间，不需要松弛变量。
2. **算不出来就报错，不静默跳过**。闭包返回的错误会拼成 `ValueError` 抛出去。
   悄悄跳过一条约束，等于「用户以为生效了、其实没有」。

## 2. 按数学形态分三类（不按用户说法分）

判尺问的是「数学上必不必要」，所以分类看**编译出来的约束长什么样**，不看
「用户会说哪句话」。下表 14 行全对着 `closure.py` 的编译函数核过。

### A 类 · 纯 0/1 线性行（7 个）

形态都是 `Σ{x : 某个选择器} ⊙ 常数`，$\odot\in\{\le,\ge,=\}$，系数只有 0 和 1。

| 槽位 | 编译出来的约束 | 编译器 |
|---|---|---|
| `count_min` / `count_max` | `Σ{组内候选} >= / <= v` | `_compile_count` |
| `bucket_min` / `bucket_max` | `Σ{组 ∧ 桶 的候选} >= / <= v` | `_compile_bucket` |
| `earliest` | `Σ{开工早于 v 的候选} == 0` | `_compile_earliest` |
| `line_fixed` | `Σ{该任务不在指定作业线的候选} == 0` | `_compile_line_fixed` |
| `scope_only` | `Σ{范围外的候选} == 0` | `_compile_scope_only` |

**数学必要：弱。** 七个槽位本质是一条通用线性行 `linear_row(selector, sense, rhs)`
的七种选择器写法。它们真正缩小的是「模型不用自己拼变量集合」这个自由度——
**这是翻译稳定性的收益，不是数学上的必需**。

**但别急着合并。** 大一修的教训是「自由度交给模型 + 信任层兜底」这条路在它那个
体量下失控；小一修反过来把说法锁在槽位里，换来的是翻译不漂移。对「小而确定」
的定位，这是刻意的取舍。所以结论是：**这 7 个保留，但承认它们是受控说法枚举；
以后不再往 A 类里加新槽位**，新说法先看能不能用现有选择器组合表达。

顺带一提，A 类里的 `scope_only` 用的是**补集压零**而不是 `Σx = N`，这正是
大一修 v0.17 出事的地方；`test_scope_exclusion.py` 已把它锁成结果级断言。

### B 类 · 带事实层常系数的线性行（3 个）

还是一条线性行，但系数不是 0/1，而是从数据层读出来的常数。

| 槽位 | 编译出来的约束 | 系数从哪来 |
|---|---|---|
| `budget_max` | `Σ 成本(c)·x <= 上限`（分组口径）或 `metrics[...] <= 上限`（整轮） | `costs.py` 的人工/备件/船舶艘天 |
| `same_bucket` | `day_of(a) == day_of(b)`，其中 `day_of = Σ (开始//1440)·x` | 候选的开工日 |
| `before_seq` | `finish_of(a) + 间隔 <= start_of(b)`，和式系数是完工/开工分钟 | 候选的开工与完工时刻 |

**数学必要：中到强。** 系数不能由用户随口给，必须从事实层取，否则「船租涨两成」
这类改动就会和约束脱节。`before_seq` 还有个隐含前提——涉及的任务必须被修，
否则和式不代表那个任务的时间；这个前提由 `apply` 的必修名单保证，属于
**结果可信**那一半，不是自由度问题。

### C 类 · 需要辅助变量或全局约束（4 个）

这几个真的不是一条线性行能表达的。

| 槽位 | 为什么需要专门结构 |
|---|---|
| `cap_max` | 先为每个实例建「是否被占用」的布尔指示（用 `AddMaxEquality` 从候选里取），再 `Σ 指示 <= v`。这是**存在性聚合**，多一层布尔变量 |
| `all_diff` | `AddAllDifferent(天/窗口序号)`，是全局互异约束，线性行只能两两写析取 |
| `sev_before` / `sev_gap` | 用 `AddMaxEquality` 取「高层最晚完工」、`AddMinEquality` 取「低层最早开工」，再比大小。两个辅助变量做层间聚合 |

**数学必要：强，保留。** 这 4 个也是复杂度的真正大头——每个都要独立的编译分支、
校验规则、对账函数，不能靠一个通用行生成器蒙过去。

## 3. 「每种说法复制一套分支」在小一修不成立

大一修的归因是「加一种说法 → 加一整套实现」。我按注册表逐个核了，小一修是
**按数学形态家族共享实现**，不是按说法复制：

| | 数量 |
|---|---|
| 闭包槽位 | 14 |
| 独立编译函数（`closure.py` 的 `COMPILERS` 去重） | 11 |
| 独立对账函数（`reconcile.py` 的 `RECONCILERS` 去重） | 11 |

复用关系：`count_min/count_max` 共用 `_compile_count` 与 `reconcile_count`；
`bucket_min/bucket_max` 共用 `_compile_bucket` 与 `reconcile_bucket`；
`sev_before/sev_gap` 共用 `_compile_sev` 与 `reconcile_sev`。

另外**14 个槽位全部声明了对账函数且全部能在 `RECONCILERS` 里找到**
（`count_*→reconcile_count`、`bucket_*→reconcile_bucket`、`cap_max→reconcile_cap`、
`budget_max→reconcile_budget` 等）。一开始按「槽位名 = 对账函数名」去搜，
会误以为有 6 个漏了对账；实际是按家族命名，没有漏。

**四件套（槽位定义 `slots.py` / 编译 `closure.py` / 对账 `reconcile.py` /
校验 `validate.py`）齐全，且都有 yxcore 测试兜着。** 这是「结果可信」那一半的
证据，也是不照搬塌缩的主要理由。

## 4. 逐类结论与「不做什么」

| 类别 | 结论 |
|---|---|
| A（7） | 保留，承认是受控说法枚举；**不新增同类**，新需求先看选择器组合 |
| B（3） | 保留，系数来自事实层，数学必要 |
| C（4） | 保留，真需要辅助变量/全局约束；是后续复杂度预算的重点 |

**明确不做**：不把 14 个槽位塌缩成「一串编号」，不把自由度交回给大模型自由写
约束，不改任何产品代码。大一修是 1.8 万行外围、1:85 的病入膏肓才做激进手术；
小一修全核心约 4500 行、四件套都有测试，没到那一步。借的是判尺和纪律，不是手术。

## 5. 以后新增槽位的准入清单

按顺序问，任一答不上来就不批：

1. **能不能写成 `Σ aᵢxᵢ ⊙ b`？** 能 → 走通用线性行，不新增槽位（A/B 类）。
2. **系数 `aᵢ` 从哪来？** 只能从事实层常数取；要用户随口给 → 拒绝。
3. **要不要辅助布尔、`max/min`、`AllDifferent`？** 要 → 写清数学必要（C 类），
   并同步补齐四件套。
4. **要不要大 M 或条件指示？** 要 → 按边界清单直接拒绝。
5. **结果怎么对账？** 没有对应的 `reconcile_*` 函数 → 不批；否则「用户说了、
   模型翻了、但没人验」。
6. **补一条结果级断言。** 用 `result_contract.check()` 或新写一条端到端用例，
   证明算出来的方案确实满足这句用户要求——而不是只证明「生成了同一个模型」。
